# ESS 피크 셰이빙 하드웨어 펌웨어

IoT 기반 ESS(Energy Storage System) 피크 셰이빙 시연 시스템의 하드웨어·펌웨어 파트입니다. 한전 인입 전류가 임계값을 넘으면 ESP32가 자동으로 릴레이를 절체해 부하 3을 배터리(ESS)로 전환하고, 피크가 해소되면 자동으로 한전으로 복귀합니다.

## 시스템 구성

- **MCU**: ESP32 DevKitC V4
- **전류 센서**: ZMCT103C (CT, 비접촉식) — 한전 인입 전류 감지
- **전류/전압 센서**: INA226 (I2C) — 배터리→인버터 전류 감지
- **절체 스위치**: 2채널 릴레이 모듈 (SZH-RLBG-042)
- **전원**: LiFePO4 4S2P 12.8V 12Ah 배터리팩 + 300W 순수 사인파 인버터

## 부하 구성

- **부하 1, 2**: 한전 상시 직결. 릴레이와 무관하게 항상 켜짐
- **부하 3**: 릴레이를 거쳐 한전(NC) ↔ 인버터/ESS(NO) 사이를 절체

## 판단 로직 (핵심 설계 원칙)

한 가지 센서만으로는 이 시스템의 절체·복귀를 전부 판단할 수 없습니다. 릴레이가 ESS로 넘어가면 부하 3은 더 이상 한전 CT를 거치지 않으므로, CT 값만으로는 "부하 3이 꺼진 것"과 "부하 3이 ESS로 넘어간 것"을 구분할 수 없습니다. 그래서 **두 센서가 서로 다른 방향을 각각 전담**합니다.

| 전환 방향 | 담당 센서 | 판단 기준 |
|---|---|---|
| 한전(NC) → ESS(NO) | CT 센서 | 한전 인입 전류가 임계값(`I_HIGH`)을 연속 2회 초과 |
| ESS(NO) → 한전(NC) | INA226 | 배터리→인버터 전류가 대기 수준(`INA_LOW_mA`) 아래로 연속 2회 하락 |

이 방식 덕분에, 부하 1·2가 항상 켜져 있어 CT 값이 절대 완전한 0으로 떨어지지 않는 이 시나리오에서도, 지연이나 깜빡임 없이 즉시 복귀가 가능합니다. (이전 버전은 15초마다 잠깐 한전으로 돌아가 확인하는 "시험 절체" 방식이었으나, INA226 도입 후 대체됨. `peak_shaving_probe.ino`에 이전 버전 보존.)

### 릴레이 결선
- **NC** = 한전
- **NO** = 인버터
- **COM** = 부하 3

### 배터리 전압 측정 (저항 분배 회로)
INA226의 `getBusVoltage_V()`가 배선·통신 모두 정상인데도 항상 0을 반환하는 알려지지 않은 문제로 인해, ESP32 ADC + 저항 분배 회로로 대체했습니다.

```
배터리(+) → R1(큰 저항) → [분기점] → R2(작은 저항) → GND
                              │
                        ESP32 GPIO35
```

- `DIVIDER_RATIO = (R1+R2)/R2`
- R1이 R2보다 최소 4.85배 이상 커야 배터리 최대 전압(약 16V)이 ESP32 한계(3.3V) 이내로 들어옴
- 현재 코드 기본값: R1=10kΩ, R2=1kΩ → 비율 11배 (실제 사용 저항에 맞게 `DIVIDER_RATIO` 수정 필요)

## 실측 확정값

- CT 보정계수 `CALIBRATION = 0.727` (전구 3개 실측 0.15V → 실제 전류 0.109A로 역산)
- 절체 임계값 `I_HIGH = 0.090A`
- INA226 대기 전류(부하3 꺼짐) 실측 약 626mA
- INA226 공급 전류(부하3 켜짐) 실측 약 800mA
- 복귀 임계값 `INA_LOW_mA = 710` (위 두 값의 중간)
- 충전 알림 기준 `CHARGE_THRESHOLD_V = 12.0V`

## 파일 구성

### 최종 통합 코드
- **`peak_shaving_core.ino`** — CT+INA226+배터리 전압+충전 LED가 모두 통합된 최종 버전. 실제 시연에 사용할 코드.

### 백업/대안 버전
- **`peak_shaving_probe.ino`** — INA226 없이 CT만으로 동작하는 이전 버전 (15초 시험 절체 방식)

### 개별 부품 테스트 (문제 발생 시 부품 단위로 격리 검증하는 용도)
- `relay_test.ino` / `relay_test_mega.ino` — 릴레이 단독 테스트 (ESP32용 / Arduino Mega 2560용)
- `ct_read_test.ino` / `ct_read_test_mega.ino` — CT 센서 단독 테스트
- `ct_raw_stream.ino` — CT 원시값을 Serial Plotter로 파형 확인
- `ina226_test.ino` / `ina226_test_mega.ino` — INA226 단독 테스트 (전압·전류 출력)
- `ina226_i2c_only_test.ino` — 전력선(IN+/IN-) 연결 전, I2C 통신만 안전하게 먼저 검증
- `ina226_diag.ino` — I2C 오류코드·오버플로우 플래그까지 포함한 정밀 진단
- `i2c_scanner.ino` — 연결된 I2C 기기의 실제 주소를 스캔
- `battery_voltage_divider_test.ino` — 저항 분배 회로 단독 테스트

## 알려진 이슈

- **INA226 Bus Voltage 버그**: 배선·I2C 통신·전류 측정 모두 정상인데 `getBusVoltage_V()`만 항상 0을 반환. 원인 미확정 (라이브러리 또는 특정 모듈 개체의 알려진 문제로 추정). 저항 분배 회로로 우회 완료.
- **INA226 측정 상한**: 사용 중인 모듈의 션트 저항이 0.1Ω(R100)이라 실질적 측정 상한이 약 800~819mA. 더 넉넉한 여유가 필요하면 0.01Ω(R010) 션트 모듈로 교체 권장 (배송 지연 중).
